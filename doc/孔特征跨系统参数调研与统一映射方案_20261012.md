# 孔特征跨系统参数调研与统一映射方案

## 1. 结论与项目基线

建议 CADProj 的第一期孔转换只覆盖三种轴对称孔：普通直孔、柱形沉孔（Counterbore）、锥形沉头孔（Countersink）。每种形状先支持单方向定深与贯穿；中间层分别表达平底和圆锥钻尖，具体孔形与孔底组合按对应版本样件验证后开放，尤其是平底沉孔/沉头孔。先限定单实体、单位置、平面入口、孔轴垂直入口，完成三系统原生读取、统一表达、原生重建及几何闭环，再扩展多位置与螺纹。

核心结构增加一个 `CHole`，继承现有 `CFeatureBase`，复用 `SweepExtent`、`CPoint3D/CVector3D`、`CRefEntityBase`、Builder/Accessor、单位转换及验证基础设施。保留有明确物理意义的少量孔参数，不建设新的规格数据库、通用轴向分段语言或独立引用框架。

本方案对应 2026-10-12 读取的仓库状态：

| 仓库或模块 | 核实结果 | 设计影响 |
|---|---|---|
| CADProj | `master` 提交 `bb2ed156c6ddee6189e94d6fbfb9fa3a80041337` | 以该提交的生产代码为准 |
| CADExchange | CADProj 固定的 gitlink 为 `d4b093b78508a64b795d82d3aac6397f24dfa169`，与本次查询的共享仓库 master 一致 | 共享模型的修改需要落在 CADExchange，再更新 CADProj 引用 |
| 现有统一模型 | `FeatureType` 尚无 `Hole`，未提供 `CHole` 或孔 Builder/Accessor | 孔为新增能力，不能标为已接线或已验证 |
| SolidWorks | README 要求 SW 2025；桥接使用 COM | 以 SW 2025 类型库验证调用签名和属性行为 |
| Creo | CMake 默认 Creo 7.0.0.0；生产代码为 `native + mapping + orchestration` | 不能套用旧文档的单文件 handler 结构，也不能直接使用 Creo 8 新增孔定位能力 |

本文中的中间定义、映射步骤和验证用例是拟议方案。API 可用性依据厂商文档及相应版本原始头文件；没有在本次环境中编译或启动 Windows CAD 程序，不能视为实机通过记录。NX 11 头文件来自第三方保存的 Siemens 原始 SDK 文件，已明确区分原始材料与官方托管来源。

## 2. 第一阶段范围与已有设计的复用

### 2.1 建议验收范围

| 对象 | 第一期 | 说明 |
|---|---|---|
| 普通直孔 | 纳入 | 平底盲孔、圆锥钻尖盲孔、单向贯穿 |
| 柱形沉孔 | 纳入 | 一段入口大圆柱 + 主孔，不包含额外入口、台阶或出口倒角 |
| 锥形沉头孔 | 纳入 | 一个入口圆锥台 + 主孔，不包含复合头部间隙或出口沉头 |
| 终止 | `VALUE`、`THROUGH_ALL` | 已有更多 `SweepExtent` 类型不代表孔适配器立即支持全部 |
| 孔位 | 单位置、单实体、法向于实际平面入口 | 孔可以位于任意朝向的平面，不局限世界 XY 平面 |
| 一个特征多个孔位 | 下一小步 | 数据可预留列表；首期发现多个位置应完整报告超范围，不能只取第一个 |
| 标准间隙孔 | 几何落在上述范围时可读取为相同孔形 | 实际直径优先；标准、规格、配合属于附加语义 |
| 螺纹孔 | 后续增量 | 需要分清钻孔实体、公称直径、装饰表示与真实螺旋牙型 |
| 斜孔、曲面入口、埋入入口、双向孔、孔系列、锥管螺纹、任意草绘孔形 | 后置 | 首期没有必要为这些功能设计一整套通用语言 |

对于已有圆形拉伸切除，继续沿用 `Extrude` 转换。第一期孔读取针对源系统的原生孔特征，不额外做从任意最终 B-rep 中识别所有圆柱凹腔的特征识别系统。

### 2.2 可直接复用的现成表达

首先复用 CADExchange 自身：`SweepExtent` 已有定值、贯穿和引用终止；`CSketchPoint`、`CSketchConstraint`、`CRefFace/CRefPlane/CRefPoint/CRefSketchSeg` 已能承载位置和依赖；长度跟随 `UnifiedModel::unit`，现有角度约定使用弧度。孔无需另建单位类、点类、面编号协议或定位约束求解器。[共享类型与特征](https://github.com/0Pursuer/CADExchange/blob/d4b093b78508a64b795d82d3aac6397f24dfa169/core/UnifiedFeatures.h)、[终止构造器](https://github.com/0Pursuer/CADExchange/blob/d4b093b78508a64b795d82d3aac6397f24dfa169/service/builders/EndConditionBuilder.h)。

外部参考以 FreeCAD `PartDesign::Hole` 和 CadQuery 的现成孔接口为主。FreeCAD 将主孔径/深度、入口沉孔、钻尖、螺纹分别表达；CadQuery 已采用 `hole(d, depth)`、`cboreHole(d, D, h, depth)`、`cskHole(d, D, angle, depth)` 的小参数集合。这些设计支持本项目采用“主孔 + 入口修饰 + 孔底”的轻量组合。参考的是参数语义和已有构造思路，不把所有标准表和高级孔选项搬入共享层。[FreeCAD 官方头文件](https://github.com/FreeCAD/FreeCAD/blob/main/src/Mod/PartDesign/App/FeatureHole.h)、[CadQuery 官方接口](https://cadquery.readthedocs.io/en/latest/classreference.html#cadquery.Workplane.cboreHole)。

标准库会根据软件版本、标准文件和配合重新推导尺寸，跨系统同名规格并不足以保证同样的实体形状。因此首期以源特征实际生效的尺寸重建；如果保留标准名称，必须与实际尺寸分开，不能让目标标准表覆盖已归一化的几何参数。

## 3. SolidWorks 读取与创建映射

SolidWorks 侧建议分别处理简单孔与孔向导。首期只转换单孔、单实体、平面法向定位的直孔、柱形沉孔和锥形沉头孔，终止限定定深与单向贯穿；读取时仍须检测多点、额外倒角和作用实体，防止把范围外的特征静默简化。

### 3.1 识别与尺寸读取

`IFeature::GetTypeName2()` 返回 `SketchHole` 时，`GetDefinition()` 对应 `ISimpleHoleFeatureData2`；返回 `HoleWzd` 时对应 `IWizardHoleFeatureData2`。这里简单孔的注册字符串是 **`SketchHole`**。`AdvHoleWzd` 属于独立的 Advanced Hole 功能，本期暂不接入。参见[官方特征类型映射](https://help.solidworks.com/2022/English/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.IFeature~GetTypeName2.html)。

简单孔读 `Diameter`、`Depth`；其 `Type` 表示终止条件，并检查拔模相关属性，只接受无拔模圆柱孔。向导孔则必须先读 `Type` 判断细分孔型，终止另读 `EndCondition`。同一物理量不能统一从一个属性读取：

| 常见向导孔 | `Type` | 主孔直径与深度 | 附加几何字段 |
|---|---|---|---|
| 直盲孔 | `swHoleBlind` | `HoleDiameter`、`HoleDepth` | `DrillAngle` |
| 直通孔 | `swHoleThru` | `ThruHoleDiameter`、`ThruHoleDepth` | 保留贯穿终止语义 |
| 柱形沉盲孔 | `swCounterBoreBlind` | `HoleDiameter`、`HoleDepth` | `CounterBoreDiameter`、`CounterBoreDepth`、`DrillAngle` |
| 柱形沉通孔 | `swCounterBoreThru` | `ThruHoleDiameter`、`ThruHoleDepth` | `CounterBoreDiameter`、`CounterBoreDepth` |
| 锥形沉头盲孔 | `swCounterSinkBlind` | `HoleDiameter`、`HoleDepth` | `CounterSinkDiameter`、`CounterSinkAngle`、`DrillAngle`、`HeadClearance` |
| 锥形沉头通孔 | `swCounterSinkThru` | `ThruHoleDiameter`、`ThruHoleDepth` | `CounterSinkDiameter`、`CounterSinkAngle`、`HeadClearance` |

Legacy 向导孔的 `swSimple`、`swCounterBored`、`swCounterSunk` 等使用 `Diameter/Depth`，应另行分派。附加入口、出口、中间沉头及 `WithoutHeadClearance` 也有各自类型。依据是[孔型与有效属性表](https://help.solidworks.com/2021/english/api/sldworksapi/Table_of_Wizard_Hole_Types_and_Valid_Properties.htm)，不能仅按枚举名字包含某个词进行归类。

### 3.2 原生创建与定位

优先采用官方已有流程：`CreateDefinition(swFmHoleWzd)` → `InitializeHole(...)` → 覆盖对应孔型的有效尺寸 → 选择定位引用 → `CreateFeature(...)`。初始化使用 `swWzdGeneralHoleTypes_e` 大类、标准、规格与终止参数，不能直接传入上述细分读取枚举。此流程见[SW2025 创建指南](https://help.solidworks.com/2025/english/api/sldworksapiprogguide/OVERVIEW/Hole_Wizard_Features_and_WizardHoleFeatureData2_Objects.htm)。标准仅用于初始化与保留语义，目标几何使用明确尺寸，不自行重建螺钉规格库。

简单孔可使用 [`IFeatureManager::SimpleHole2`](https://help.solidworks.com/2024/english/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.IFeatureManager~SimpleHole2.html)。向导孔备选为 [`HoleWizard5`](https://help.solidworks.com/2021/english/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.IFeatureManager~HoleWizard5.html)，把其长参数表封装在适配器内部。该接口长度用米、角度用弧度；`-1` 表示忽略参数，不能据此认定附加选项已关闭。

向导孔通过 `GetSketchPoints()` 获取中心定位点；其定位草图与剖面草图必须区分。首期检测点数恰为一，利用项目已有草图坐标变换得到模型坐标，并核对支撑平面与朝材料内部的轴向。向导孔也支持三维定位和多面多点，因此超出范围时应明确报告。参见[定位草图说明](https://help.solidworks.com/2024/english/SolidWorks/sldworks/HIDD_DVE_HW_INSERT_HOLE.htm)。

方向读取 `ReverseDirection`；作用范围读取 `FeatureScope`、`FeatureScopeBodies`、`AutoSelect`，确认只影响指定实体。`Face/Vertex` 是**终止引用**，不是入口定位引用，且部分 setter 未实现；如需设置应走 `SetEndConditionReference`。读取引用时沿用项目已有选择访问封装，纯读取结束须释放访问。成员依据见[SW2025 接口表](https://help.solidworks.com/2025/English/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.IWizardHoleFeatureData2_members.html)。

### 3.3 保持几何一致的边界

SolidWorks 界面允许深度到钻肩或钻尖，但本轮未找到 `IWizardHoleFeatureData2` 对该开关可靠的公开读写成员。不能默认 `HoleDepth` 必然表示到钻肩，也不能借用独立 Advanced Hole 的参数来解释它。需用 SW2025 同尺寸、两种深度标注的模型，核对 API 值与圆柱段、圆锥段实际尺寸；不确定时报告未支持，或由明确限定的几何检查恢复。参见[孔深选项说明](https://help.solidworks.com/2022/English/SolidWorks/sldworks/r_HIDD_DVE_HW_HOLE_SPEC.htm)。

`HeadClearance` 会参与实际沉孔尺寸；归一化时应核对源孔特征完成阶段的几何，目标创建避免再次叠加。入口、出口、台阶处的附加沉头同样不能遗漏。首期只接受简单截面；非零间隙只有在能够准确折算为规范尺寸时才接受，带额外几何则明确列为暂不支持。以上为接口调研与实施方案，尚未在 SW2025 中编译运行验证。

## 4. Creo 读取与创建映射

### 4.1 按原生孔分类读取，按实际几何选择创建分支

首期建议限定为**单孔、单实体、平面入口、孔轴垂直入口、单向定长或贯穿**。Creo 接收端可使用已有的 Straight 和 Custom 孔：前者处理平底圆柱孔，后者处理钻尖、圆柱沉孔和圆锥沉孔。Custom 能填写显式尺寸，适合接收其他系统的非标准尺寸；无需为了创建这些孔维护一套自有标准数据库。

两类都是 `PRO_FEAT_HOLE`，必须读取 `PRO_E_HLE_TYPE_NEW` 后再选择参数路径。Straight 的 `PRO_E_FEATURE_FORM` 为 `PRO_HLE_TYPE_STRAIGHT`；Custom/Standard 为 `PRO_HLE_TYPE_SKETCHED`。这里的 Form 名称表示构造形式，不能据此把 Custom 误判成用户自绘孔。[公共类型定义](https://support.ptc.com/help/creo_toolkit/protoolkit_plus/usascii/creo_toolkit/user_guide/Common_Element_Values.html)

| 参数角色 | Straight 分支 | Custom 分支 |
|---|---|---|
| 孔类型 | `PRO_E_HLE_TYPE_NEW = PRO_HLE_NEW_TYPE_STRAIGHT` | `PRO_E_HLE_TYPE_NEW = PRO_HLE_CUSTOM_TYPE` |
| 实际孔径，double | `PRO_E_DIAMETER` | `PRO_E_HLE_HOLEDIAM` |
| 深度类型，**int 枚举** | `PRO_E_HOLE_STD_DEPTH / PRO_E_HOLE_DEPTH_TO / PRO_E_HOLE_DEPTH_TO_TYPE` | `PRO_E_HLE_DEPTH` |
| 定长深度，**double 数值** | `PRO_E_EXT_DEPTH_TO_VALUE`，位于前述 TO 子树 | `PRO_E_HLE_DRILLDEPTH` |
| 首期终止枚举 | `PRO_HLE_STRGHT_BLIND_DEPTH` / `PRO_HLE_STRGHT_THRU_ALL_DEPTH`；另一侧设 `PRO_HLE_STRGHT_NONE_DEPTH` | `PRO_HLE_STD_VAR_DEPTH` / `PRO_HLE_STD_THRU_ALL_DEPTH` |
| 钻尖与深度基准 | 平底圆柱，不设置钻尖 | `PRO_E_HLE_DRILLANGLE`、`PRO_E_HLE_DEPTH_DIM_TYPE` |
| 圆柱沉孔 | 转用 Custom | `PRO_E_HLE_ADD_CBORE`、`PRO_E_HLE_CBOREDIAM`、`PRO_E_HLE_CBOREDEPTH` |
| 圆锥沉孔 | 转用 Custom | `PRO_E_HLE_ADD_CSINK`、`PRO_E_HLE_CSINKDIAM`、`PRO_E_HLE_CSINKANGLE` |
| 切除方向 | TO/FROM 两侧深度定义 | `PRO_E_HLE_CRDIR_FLIP` |

表中深度类型与深度数值不可混用，沉孔开关也应按 SDK 枚举填写，不能全部转换成 0/1。Straight 的第二侧仍有 FROM 复合节点；具体必需项按 SDK 的完整树构建。[Straight 定义](https://support.ptc.com/help/creo_toolkit/protoolkit_plus/usascii/creo_toolkit/user_guide/Straight_Hole.html)、[Custom 定义](https://support.ptc.com/help/creo_toolkit/protoolkit_plus/usascii/creo_toolkit/user_guide/Custom_Hole.html)、[子元素语义](https://support.ptc.com/help/creo_toolkit/protoolkit_plus/usascii/creo_toolkit/user_guide/Valid_PRO_E_HLE_COM_Sub_Elements.html)

### 4.2 深度、放置与几何一致性

盲孔应把深度归一到统一入口基准。Custom 的 `PRO_E_HLE_DEPTH_DIM_TYPE` 区分 `PRO_HLE_DEP_SHOULDER_DIM_SCHEME` 与 `PRO_HLE_DEP_TIP_DIM_SCHEME`，即到圆柱段末端或到钻尖。孔元素角度以度表示；长度按模型单位转换到项目共享约定。不能直接复制各系统界面上的“深度”数字。[ProHole.h](https://support.ptc.com/help/creo_toolkit/protoolkit_plus/usascii/creo_toolkit/api/dita/prohole_h.html)

共享层保存一个深度数值与肩/尖基准，几何计算时再派生到圆柱段末端的轴向长度。设孔径为 D、钻尖全夹角为 α，则钻尖长度为 `(D/2)/tan(α/2)`；到钻尖的深度减去此值才是到钻肩的长度。这是圆锥几何推导，不应把底层锥面的半角直接赋给孔特征。单位可通过 `ProMdlPrincipalunitsystemGet` 获取模型单位系，再用 `ProUnitConversionCalculate` 换算；不要假定所有 Creo 零件均采用毫米。[单位访问](https://support.ptc.com/help/creo_toolkit/protoolkit_plus/usascii/creo_toolkit/user_guide/Accessing_Individual_Units.html)

原生放置参数与解析后的显式坐标应分层保存：native 层保留主引用、偏置引用、距离及翻转状态；中间层复用已有引用和 `CSketch` 可表达的定位约束，同时保留归一化入口点、轴向。Writer 优先恢复依赖，无法对应时再按解析位置创建辅助基准并记录关联降级。

Linear 放置使用 `PRO_E_HLE_PRIM_REF`、两组 `PRO_E_HLE_DIM_REF1/2` 和 `PRO_E_HLE_DIM_DIST1/2` 等节点。两条参考边需在放置面内且不平行；不能任取两条边充当定位约束。[Linear 放置要求](https://support.ptc.com/help/creo_toolkit/protoolkit_plus/usascii/creo_toolkit/user_guide/Linear_Hole_on_a_Plane.html)

另可用基准点放置，但“点投影到放置面”与“点加方向引用”具有不同深度起点。首期应让点位于入口平面，避免投影使孔深悄悄改变。[基准点与放置面](https://support.ptc.com/help/creo_toolkit/protoolkit_plus/usascii/creo_toolkit/user_guide/Onpoint_Hole_with_Primary_Reference_as_Datum_Point.html)

`PRO_E_HLE_TOP_CLEARANCE` 会改变实体：它可按孔顶部直径向外延伸圆柱并切除材料，包含沉孔或锥窝的顶部直径。Reader 应识别其作用；首期平面入口场景可减少差异，不能把它当显示选项统一开启。[Creo 7 孔界面说明](https://support.ptc.com/help/creo/creo_pma/r7.0/usascii/part_modeling/part_modeling/part_nine_sub/About_the_Hole_Feature_User_Interface.html)

### 4.3 创建流程、标准信息与版本边界

读取使用 `ProFeatureElemtreeExtract`，外部引用需正确组件路径，提取树以 `ProFeatureElemtreeFree` 释放。创建按官方顺序构造完整树，调用 `ProFeatureWithoptionsCreate`，检查错误列表、特征状态及再生；自行构造的树按对应元素生命周期释放。可复用官方 `UgHoleCreate.c` 的构建方式，但样例允许界面补齐缺失元素，生产 Writer 应自行补全。[提取 API](https://support.ptc.com/help/creo_toolkit/protoolkit_plus/usascii/creo_toolkit/api/dita/1494.html)、[创建示例](https://support.ptc.com/help/creo_toolkit/protoolkit_plus/usascii/creo_toolkit/api/samples/UgHoleCreate_c.html)

标准孔的系列/规格应通过 `ProElementHoleThreadSeriesGet/Set` 和 `ProElementHoleScrewSizeGet/Set` 读写名称，不能跨机器复制 `.hol` 列表下标；创建时先设系列，再设规格。实际钻孔尺寸仍独立保存。标准缺失时应保留元数据并报告，不能改用近似规格。[孔专用函数](https://support.ptc.com/help/creo_toolkit/protoolkit_plus/usascii/creo_toolkit/user_guide/Hole_specific_Functions.html)

验收要包含**编辑定义、修改尺寸、再次再生**。官方特别指出，某些标准螺纹孔即使当前贯穿、不使用某个深度值，也需保留相应深度节点，否则可能创建成功却不能在界面重定义。[标准螺纹孔必需项](https://support.ptc.com/help/creo_toolkit/protoolkit_plus/usascii/creo_toolkit/user_guide/Standard_Threaded_Hole.html)

版本上，官方 Creo **5.0.0.0** 手册已列 Custom 与深度基准节点，支持把它作为 Creo 7 的实施路线；本次未完成用户 SDK 的编译和样件再生。**草图点放置多个孔是 Creo 8 新增**，不能将新版 `PRO_E_HOLE_SKDP_OPTIONS` 路线直接用于 Creo 7。将来接收多孔位置时，Creo 7 可逐孔创建并保留源特征分组关系。[早期 TOOLKIT 手册，第 896、900 页](https://support.ptc.com/images/cs/articles/2018/05/1525425932uNM3/tkuse.pdf)、[PTC 的 Creo 8 多孔说明](https://www.ptc.com/en/blogs/cad/adding-holes-your-creo-design-2021)

实施前尚需在 Creo 7 样件上确认 Custom 的精确必需节点、平底角度边界及角度到锥面半角的换算；这些通过少量同版本树提取和再生实验解决即可。

CADProj 当前面向 NX 11，本轮建议优先用 `NXOpen::Features::HolePackageBuilder` 创建孔，同时为旧 `Hole` 特征保留读取分支。已经核对第三方保存的 Siemens **NX 11.0.2.7 原始 SDK 头文件**，并与 Siemens 生成的 API 参考文档镜像交叉检查；以下是接口级调研，尚未在 NX 实机编译、创建和回读验证。[NX 11 孔构建器头文件](https://github.com/ugopen/nxopen_lib/blob/96855b43415ac81dcfdc83f8874ea5622c19d2db/NX11.0.2.7/UGOPEN/NXOpen/Features_HolePackageBuilder.hxx)

### 5.1 现代孔：按形状读取对应参数

读取已有 `HolePackage` 时，通过 `CreateHolePackageBuilder(existingHolePackage)` 取得参数；完成后销毁 builder，无须提交修改。写入本轮三种孔采用 `TypesGeneralHole`，再选择相应 `GeneralHoleForm`，以实际尺寸控制几何。以下表达式 getter 返回 `Expression*`，不是普通 `double`。[构建器 API 参考文档镜像](https://www.ugapi.com/doc/nxopen/a02873.html)

| 中间定义中的含义 | NX 11 对应入口 | 映射要点 |

**NX 11 已有钻尖计深选项。** 原始头文件明确将 `DepthOption` 的读写标为 NX 11.0.0 引入，默认量到圆柱底。中间结构可以只保存一个深度和一个 `depthReference` 枚举；写入时直接匹配，或者先按钻尖几何换算。这样不必同时持久化两个可能失配的深度值。[NX 11 声明及默认值](https://github.com/ugopen/nxopen_lib/blob/96855b43415ac81dcfdc83f8874ea5622c19d2db/NX11.0.2.7/UGOPEN/NXOpen/Features_HolePackageBuilder.hxx)

`GetOrigins` / `GetDirections` 自 NX 5.0.3 已存在，是读取已求值位置的直接入口。若还要恢复定位约束，可以沿 `Section::GetSectionData` → `SectionData::GetSectionElementsData` → `SectionElementData::GetSectionElementData1` 读取引用；最后一个接口能返回点，旧的 `GetSectionElementData(ICurve**)` 不适合作为点定位的统一入口。创建单点位置可使用 `CreateRuleCurveDumbFromPoints` 与 `Section::AddToSection`。[孔对象头文件](https://github.com/ugopen/nxopen_lib/blob/96855b43415ac81dcfdc83f8874ea5622c19d2db/NX11.0.2.7/UGOPEN/NXOpen/Features_HolePackage.hxx)、[定位元素头文件](https://github.com/ugopen/nxopen_lib/blob/96855b43415ac81dcfdc83f8874ea5622c19d2db/NX11.0.2.7/UGOPEN/NXOpen/SectionElementData.hxx)、[点选择规则头文件](https://github.com/ugopen/nxopen_lib/blob/96855b43415ac81dcfdc83f8874ea5622c19d2db/NX11.0.2.7/UGOPEN/NXOpen/ScRuleFactory.hxx)

### 5.2 旧式孔：保留兼容读取，谨防参数顺序

旧孔可用 `Features::Hole` 的形状与尺寸 getter，或 UFUN 的 `UF_MODL_ask_simple_hole_parms`、`UF_MODL_ask_c_bore_hole_parms`、`UF_MODL_ask_c_sunk_hole_parms`。对应创建函数真实名称为 `UF_MODL_create_simple_hole`、`UF_MODL_create_c_bore_hole`、`UF_MODL_create_c_sunk_hole`。这些入口面向旧式孔，不能据此认定能完整读取现代孔包。[旧孔对象参考](https://www.ugapi.com/doc/nxopen/a02870.html)、[NX 11 UFUN 孔头文件](https://github.com/ugopen/nxopen_lib/blob/96855b43415ac81dcfdc83f8874ea5622c19d2db/NX11.0.2.7/UGOPEN/uf_modl_holes.h)

| UFUN 参数 | 读取 `ask_*` 的含义 | 创建 `create_*` 的含义 |
|---|---|---|
| 沉孔 `diameter1 / diameter2` | 入口大径 / 底孔小径 | 底孔小径 / 入口大径 |
| 沉孔 `depth1 / depth2` | 沉孔深 / 底孔深 | 底孔深 / 沉孔深 |
| 沉头孔 `diameter1 / diameter2` | 入口大径 / 底孔小径 | 底孔小径 / 入口大径 |

上表的不对称是实际头文件定义，适配层应采用语义明确的局部变量。`ask_*` 返回的尺寸是表达式字符串，并要求 `UF_free` 释放；不要直接对完整字符串调用数值解析。旧创建接口需要放置面与贯穿终止面，方向要求垂直放置面并朝向实体内部；一旦指定贯穿面，数值孔深即被忽略，因此这个“贯穿面”不能无条件转换成中间定义的“贯穿全部”。[UFUN 参数与约束说明镜像](https://www.ugapi.com/doc/UFun/uf_modl/uf_modl_holes.html)

### 5.3 单位、坐标与实施边界

长度读取应尊重表达式单位或零件基准单位，再转换到 CADProj 的统一单位。旧 `Expression::Value()` / `GetValueUsingUnits(UnitsOptionBase)` 不能视为固定毫米值；需要时利用 `UnitCollection::GetBase`、`Convert` 转换。[表达式单位说明](https://www.ugapi.com/doc/nxopen/a02625.html)、[NX 11 单位转换声明](https://github.com/ugopen/nxopen_lib/blob/96855b43415ac81dcfdc83f8874ea5622c19d2db/NX11.0.2.7/UGOPEN/NXOpen/UnitCollection.hxx)

NX 11 孔角表达式的默认钻尖角为 118，沉头角为公制 90、英制 82，按度处理；进入三角函数前转换到弧度。不要据此推断所有 NX 几何 API 都使用度，例如 UF 圆弧角明确使用弧度。UF 点坐标读取 `UF_CURVE_ask_point_data` 与旧特征位置 `UF_MODL_ask_feat_location` 明确返回绝对坐标；前者可作为孔位交叉校验入口。[孔角默认值](https://github.com/ugopen/nxopen_lib/blob/96855b43415ac81dcfdc83f8874ea5622c19d2db/NX11.0.2.7/UGOPEN/NXOpen/Features_HolePackageBuilder.hxx)、[点坐标与圆弧角说明](https://www.ugapi.com/doc/ufun/uf_curve/uf_curve.html)、[旧特征位置说明](https://www.ugapi.com/doc/ufun/uf_modl/uf_modl.html)

实施时仍要用 NX 11 小样本确认平底孔的原生角度编码、入口延伸设置及原点对应关系。现代 writer 优先设置完整孔参数并回读验证；超出单位置、单实体、平面法向以及本轮终止方式的情况，应明确报告超范围。`ThroughBody` 在首期单实体范围内映射为 `THROUGH_ALL`；不能拿任意大数代替其设计意图。

## 6. 建议的最小中间定义

### 6.1 语义先于字段名

统一把每个孔的实际入口平面作为轴向零点，孔轴向材料内部的方向作为正方向。`entryPoint` 是孔轴与该入口平面的交点，使用模型坐标；`direction` 是模型坐标中的单位向量。主孔深和沉孔深都从这同一入口量起。

保留一个深度数值和一个深度基准枚举：`extent.value + depthReference`。不同时保存两份可被独立修改的“钻肩深”和“钻尖深”。需要几何计算时，再派生从入口到主孔钻肩的长度 `L_s` 和到钻尖的长度 `L_t`。这样既能消除数值歧义，也能保留“用户改深度时控制哪个端点”的意图。

`counterbore` 和 `countersink` 第一阶段互斥：都没有是普通直孔；只出现前者是柱形沉孔；只出现后者是锥形沉头孔。无需另外保存一份容易与参数互相矛盾的孔型字符串。`Hole` 自身固定表示减材，无需再次存一个可被误设为增材的 `operation`。

### 6.2 C++ 结构草案

下面是共享模型的拟议结构，展示字段职责，尚未接入代码、序列化或 SDK。真实实现继续通过现有 Builder 写入、Accessor 读取。

```cpp
// 位于 CADExchange 命名空间；复用已有几何、引用与终止类型。
enum class HoleBottomKind { Unknown, Flat, Conical };
enum class HoleDepthReference { Unknown, Shoulder, Tip };

struct CHoleLocation {
    CPoint3D entryPoint;  // 模型坐标；位于实际入口平面
    std::shared_ptr<CRefEntityBase> positionRef; // 可选：已有点/草图点引用
};

struct CHoleCounterbore {
    double diameter = 0.0; // 入口大径
    double depth = 0.0;    // 从实际入口到台阶平面
};

struct CHoleCountersink {
    double diameter = 0.0;      // 入口大径
    double includedAngle = 0.0; // 全锥角，弧度；轴向高度派生
};

struct CHole : CFeatureBase {
    std::shared_ptr<CRefEntityBase> supportRef; // 放置面/基准面
    CVector3D direction{};                     // 向内、单位向量
    std::vector<CHoleLocation> locations;      // 首期必须恰好一个

    double diameter = 0.0;                    // 主孔实际圆柱直径
    SweepExtent extent;                       // 首期 VALUE / THROUGH_ALL
    HoleDepthReference depthReference = HoleDepthReference::Unknown;
    HoleBottomKind bottom = HoleBottomKind::Unknown;
    std::optional<double> drillPointAngle;     // Conical 时的全顶角，弧度

    std::optional<CHoleCounterbore> counterbore;
    std::optional<CHoleCountersink> countersink;

    CHole() { featureType = FeatureType::Hole; } // 需要新增枚举成员
};
```

这几个小结构只描述孔特有的物理意义。`supportRef` 与 `positionRef` 必须分开：前者说明起始支撑，后者说明孔中心的定位依赖。位置列表从一开始避免把结构锁死为单点，但能力验证仍明确拒绝首期范围外的多位置输入。

### 6.3 与现有模型衔接的约束

| 字段或情况 | 第一期合同 |
|---|---|
| 长度 | 跟随 `UnifiedModel::unit`；转换由现有 `ConvertModelUnit` 统一处理 |
| 角度 | 共享层使用弧度；孔锥角和钻尖角都为完整夹角 |
| 数值有效性 | 激活的尺寸、坐标与方向分量均须有限；孔径与入口段长度为正；方向非零并归一化；圆锥钻尖角与沉头角满足 `0 < angle < π` |
| `extent.type == VALUE` | `value > 0`；孔底已知；圆锥底必须已解析肩/尖基准和有效顶角，派生的 `h_tip/L_s/L_t` 均为有限值，并要求 `L_s > 0`；纯圆锥或主孔圆柱段消失的情况首期报超范围 |
| 平底盲孔 | 肩与尖重合，可规范为 Shoulder；不得用未知角度或任意默认钻尖替代 |
| `extent.type == THROUGH_ALL` | 不用某个有限 `value`、读回的通孔深或隐藏钻尖参数决定几何；忽略不活跃的盲孔末端字段 |
| 复用 `SweepExtent` 的其他字段 | 第一阶段 `isFlip/isFlipMaterialSide/hasOffset` 均为 false，offset 为 0；方向已归入 `direction`。其他终止或引用偏移先报超范围 |
| 入口形态 | 两个 optional 至多出现一个；大径必须大于主孔径 |
| 盲孔入口段 | 沉孔深、或由沉头大径与角度派生的入口高度，小于 `L_s`；先排除主孔圆柱段消失的退化/重叠组合 |
| 孔位与入口 | 位置在支撑平面上，方向与平面法向平行且指向实际切除侧；不能默认为世界 Z 或仅复制 Reverse 布尔量 |
| 实体范围 | 首期仅单实体零件；后续依赖公共实体身份/映射扩展目标集合，不新增一套孔专用 Body 标识 |

`Unknown` 表示尚未建立可靠映射，不能作为默认平底、默认肩深或默认 118° 钻尖使用。对于贯穿这类没有实际孔底的情况，未知孔底不影响有效的贯穿语义。

### 6.4 定位关联的保存程度

必须同时区分“实际位置正确”与“定位关系保留”。源 API 读取的二维尺寸、线性/径向定位引用、草图约束先保留在系统原生读取结果中。能通过现有 `CSketch/CSketchConstraint` 与引用体系等价表达的，复用现有草图和约束转换；共享 `CHole` 只引用对应位置。不能等价表达的定位关系，不另写简化求解器，也不能只保留三维坐标便宣称所有设计意图保真。

首期可以明确把已求值入口位置作为几何重建依据，同时在结果中报告定位关联是否保持。目标仍需生成可编辑的原生孔，允许后续修改孔径和深度；“支撑/定位尺寸随上游修改联动”是另一个需要单独验收的能力。源已经有可映射定位约束时，优先沿用，不主动丢弃。

## 7. 几何一致性与转换规则

### 7.1 钻肩、钻尖与沉孔深度

设主孔直径为 `d`，钻尖完整顶角为 `theta`，入口到主孔圆柱末端（钻肩）的距离为 `L_s`。对于未退化的圆锥底：

\[
h_{tip}=\frac{d}{2\tan(\theta/2)},\qquad L_t=L_s+h_{tip}.
\]

因此当唯一存储的 `extent.value` 为 `L`：

\[
L_s=\begin{cases}
L & \text{Shoulder 或平底},\\
L-h_{tip} & \text{Tip 且圆锥底}.
\end{cases}
\]

例如 `d=10 mm`、顶角 `118°`、钻肩深 `20 mm`，钻尖高度约为 `3.004303 mm`，到钻尖深度约为 `23.004303 mm`。如果把 `20 mm` 原样填给“到尖”的目标，则圆柱段仅约 `16.995697 mm`，会留下明显的多余材料。上述数值是几何推导，不是任何 CAD 的默认解释。

柱形沉孔还必须分清：`counterbore.depth` 从入口到台阶，而 `L_s` 从入口到主孔钻肩。若某原生接口给出的是台阶以下的长度，映射时要加回沉孔深；已经从入口量起的不能再加。字段都叫 HoleDepth 不是判断依据。

### 7.2 锥形沉头用直径和全角定义

设入口沉头直径为 `D`、主孔直径为 `d`、完整沉头角为 `alpha`，入口圆锥台的轴向高度是：

\[
h_{csink}=\frac{D-d}{2\tan(\alpha/2)}.
\]

例如 `d=6.6 mm`、`D=12.6 mm`、`alpha=90°`，入口高度为 `3 mm`。将其作为一个精确圆锥台解释，既可验证原生创建，也可供既有预览层计算。不要把完整孔角与底层锥曲面常用的半角混用，也不要把沉头大径当半径。

头部间隙、近端/中间/远端倒角、Creo Top Clearance 等可能改变有效入口。能证明其作用完全折入同一圆柱或圆锥台的，先归一到实际尺寸，再避免目标重复加一次；无法证明仍属于三种首期形状的，报告超范围。直接关闭源端有几何作用的附加选项会改变形状。

### 7.3 孔深未知时如何处理

Creo Custom 的深度基准枚举、NX 11 的 `DepthOption` 有直接依据。SolidWorks 本轮未找到 Hole Wizard 对应肩/尖 UI 开关的可靠公开读写成员，因此该项是实现前最优先的本机校准任务。

建议先制作 SW2025 同一数值、分别肩深/尖深的成对样件，提取 feature data 与该孔完成阶段的解析几何，确认读取属性到底返回什么。必要时用入口平面、圆柱末端和圆锥尖求出真实 `L_s/L_t`，与 API 数值匹配后判定语义；能得到几何但无法恢复原始标注方式时，可以显式采用已知几何的规范表达，并报告标注语义变化。

这个办法有边界：盲孔末端可能已经在实体外，孔底可能被其他切除吞掉，单凭实体几何不能恢复全部潜在参数。这些情况下必须依赖可靠原生数据或标记未解析，不能假定到肩。几何核查应针对孔特征刚完成的历史状态；最终模型可能已经被下游圆角、交叉孔或切除改变，不能反推原始孔参数。

### 7.4 单向贯穿保持终止语义

源端贯穿在中间层仍是 `THROUGH_ALL`，目标优先使用自己的原生贯穿选项。源端定深即使碰巧打穿当前薄板，也仍应保留 `VALUE`。通过把贯穿换成 40 mm、1000 mm，或孔轴与背面交点处的厚度，无法可靠覆盖斜背面、厚度变化、空腔及指定实体范围。

后续若某个明确支持的几何降级路径必须使用有限切削工具，长度只能根据目标实体在切削方向的几何包络和既有容差推导，并报告终止关联改变；第一期三个原生 Writer 不需要引入这种替代路径。

### 7.5 原生重建与有限的几何展开

| 中间形状 | SolidWorks 目标 | Creo 7 目标 | NX 11 目标 |
|---|---|---|---|
| 普通平底圆柱孔 | `SimpleHole2`；或者已验证支持平底的向导创建配方 | Straight Hole | General Hole 的对应平底能力，需确认本机 API 编码 |
| 普通圆锥底盲孔 | Hole Wizard，显式钻尖与深度 | Custom Hole | General Simple，显式 TipAngle 与 DepthOption |
| 柱形沉孔 | Hole Wizard Counterbore | Custom + Counterbore | General Counterbore |
| 锥形沉头孔 | Hole Wizard Countersink | Custom + Countersink | General Countersink |

特别是平底沉孔/沉头盲孔，不能未经同版本验证便把 `180°` 当作所有 CAD 通用的平底编码。中间层用独立 Flat 语义；目标按已核实的原生开关、类型或有效数值范围实现。若目标版本的对应原生形式确实不能表达，才考虑受控的等价展开，且不把 API 偶发失败等同于“不支持”。

可借鉴 FreeCAD 的轴截面旋转做几何等价表达：在包含孔轴的平面中，依据主孔、台阶/锥台和钻尖构造封闭轮廓，使用现有旋转切除表达一个减材特征；纯平底直孔则可复用圆草图与拉伸切除。该路线只作为后续显式“几何等价展开”策略，必须报告原生 Hole 语义/特征数量是否改变、保留源到目标特征对应，并通过相同几何门禁。第一期优先原生孔，不新增通用分段定义或孔专用 B-rep 引擎。[FreeCAD 原生孔构造源码](https://github.com/FreeCAD/FreeCAD/blob/main/src/Mod/PartDesign/App/FeatureHole.cpp)。

CadQuery 的便捷孔函数可供已有 GUI 预览参考，但不能自动代替钻尖、原生终止及历史语义，更不能用与 Writer 共用的错误公式生成“参考实体”再证明自身正确。几何验收应使用源 CAD 导出的参考实体。

### 7.6 跨系统路线

三个 Reader 都输出同一 `CHole` 合同，三个 Writer 都从它取值，无需维护 SW→Creo、Creo→SW、SW→NX 等六套互不共享的参数转换代码。方向、入口原点、深度基准和有效尺寸归一化放在公共语义边界；COM 选取、Toolkit 元素树、NX Builder 与标准初始化仍留在各自系统。

同一源孔从标准表驱动转换为目标的显式尺寸孔时，几何可以相同，标准关联却可能变化。结果应分别报告“几何通过”“孔特征/参数可编辑”“定位与标准关联保持程度”，不能合并成一句含糊的无损转换。

### 8.2 三套桥接

| 模块 | 按当前代码结构增加的内容 |
|---|---|
| SW | `src/internal/feature_hole.h/.cpp` 的读/写 handler；读取 registry 注册 `SketchHole` 与 `HoleWzd`；写入 registry 注册 `FeatureType::Hole`；复用选择、坐标转换及当前拓扑缓存 |

Creo 的旧 `code_structure.md` 和早期 registry 说明有历史描述，当前 CMake 与源文件已采用分层结构。因此不能为了照搬旧说明，把新增 Creo native 读写与公共映射重新混入一个旧 internal 文件。[Creo 当前快照](https://github.com/0Pursuer/CADProj/blob/bb2ed156c6ddee6189e94d6fbfb9fa3a80041337/CreoLibs/read_write/src/mapping/model/creo_model_snapshot.h)、[模型 mapper](https://github.com/0Pursuer/CADProj/blob/bb2ed156c6ddee6189e94d6fbfb9fa3a80041337/CreoLibs/read_write/src/mapping/model/creo_model_mapper.cpp)。

还发现一个与新增类型直接相关的边界：SW 写 registry 的数组容量按 `MirrorPattern + 1` 固定，NX 按 `DatumPlane + 1` 固定。把 Hole 附加到枚举末尾后，必须同步调整 registry 的合法范围/容量与 SW 对应索引检查，否则可能出现“写了注册代码却没有实际注册”的问题。这里应做针对性的范围修正，无需借孔功能重构整个框架。[SW registry 头文件](https://github.com/0Pursuer/CADProj/blob/bb2ed156c6ddee6189e94d6fbfb9fa3a80041337/SwLibs/read_write/src/internal/feature_dispatcher.h)、[NX registry 头文件](https://github.com/0Pursuer/CADProj/blob/bb2ed156c6ddee6189e94d6fbfb9fa3a80041337/UgLibs/read_write/src/internal/feature_dispatcher.h)。

## 9. 最小验证与实施顺序

### 9.1 先解决五个会影响方案成败的本机问题

1. SW2025：肩深/尖深 UI 对原生读取值及所选创建路径的实际影响，能够确定深度基准或可靠的几何归一化方式。
2. Creo7：用同版本有效样件提取 Custom 元素树，确定完整必要节点、无交互创建与编辑定义后再生。
3. NX11：用现代 General Hole 验证三种孔型、DepthOption、点/方向与盲孔平底的有效表达。
4. 三系统：核对沉孔主深与沉孔深的起算面，以及 HeadClearance/TopClearance 等附加项是否改变首期轮廓。
5. 原生孔位：复用现有面/点引用后，目标孔心、方向和支撑与源是否一致。

### 9.2 建议的核心样件

| 样件 | 重点 |
|---|---|
| Ø10、深20的平底盲孔 | Flat 与 Conical 不混用 |
| Ø10、118°、钻肩20的盲孔 | 目标钻尖应约为23.004303；验证角度单位 |
| 同一几何改用钻尖深标注 | 数值/基准换算；不能直接复制一个20 |
| 单向贯穿，背面倾斜或改变基体厚度 | 保持贯穿终止与正确切削范围 |
| 主孔Ø6.6、沉孔Ø11、沉孔深6 | 主深起点、台阶位置与非默认尺寸覆盖 |
| 主孔Ø6.6、沉头Ø12.6、90°与82°变体 | 完整锥角与入口高度 |
| 非零原点、反向/旋转支撑平面 | 草图局部坐标、模型坐标与钻入正向 |
| 相同几何的inch模型 | 每个长度与位置都进入统一缩放 |
| 超范围对照：多位置、额外入口/出口锥窝或多实体 | 明确报告范围，不能遗漏孔位或误切实体 |

先完成三套系统各自的读→写→回读，再跑六个有向跨系统组合。首期失败应保留失败原因与源数据；能力表只登记实际覆盖的孔型、版本及终止组合。

### 9.3 沿用既有闭环门禁

继续使用仓库的 `build_all_read_write.ps1`、`run_roundtrip.ps1` / `run_roundtrip_batch.ps1`、结构校验、二次读取和 XML 比较。测试产物放项目 `tmp/`，源 `CADparts/` 维持基准用途。[仓库工作流](https://github.com/0Pursuer/CADProj/blob/bb2ed156c6ddee6189e94d6fbfb9fa3a80041337/README.md)。

几何上优先复用现有 STEP 实体比较。新增孔的验收样件要检查双向差集 `S_source - S_target` 与 `S_target - S_source`，确认布尔操作与形体有效，再按现有几何和体积容差决策；新能力验收保留完整布尔证据，不凭外观、净体积相等或快速描述符判断通过。孔位置错开时，等量增减材料可能让净体积差为零。对钻尖这类小局部差异，还应核对孔轴截面、圆柱段长度、锥角与台阶位置，避免只看整零件的相对体积比例。

参数检查不能只比较源和目标都可能读错的同一字段。应同时对照源原生尺寸、归一化解释与独立导出的源实体；比较孔数、入口点、方向、主径、入口尺寸、孔底和终止语义。拓扑面/边的数量可能随内核发生分割，不作为几何相同的充分或必要条件。

最后补一项编辑验证：修改孔径/盲深，执行再生，保存并重开后再次读取。只有“创建成功”不能说明目标原生孔真正可编辑。定位约束联动与标准表关联另列验收，不与静态几何结果混为一项。[现有 STEP 对比规范](https://github.com/0Pursuer/CADExchange/blob/d4b093b78508a64b795d82d3aac6397f24dfa169/doc/STEP终态实体几何对比规范与自适应容差说明_20260804.md)。

## 10. 后续增量的边界

多位置时先保持同规格、同一平面与同一钻入方向。SW/NX 可以保留孔组；Creo7 需要逐孔创建或使用已有阵列能力，并维护源特征到多个目标特征的对应。后续圆角、引用或阵列种子不能仍假设一个来源 ID 只对应一个原生特征。对于要求一一对应特征树的转换，这条路线应明确标为结构变化；Creo8及以上可单独增加原生多点孔的能力分支。

螺纹孔扩展再增加实际钻孔几何之外的标准/系列、规格、螺距、螺纹方向、螺纹深度及表示方式。装饰螺纹与真实牙型分开处理；实际减材直径不能由 M6 等名称直接推导，更不能把装饰螺纹统一改成公称直径孔。首期三类孔无需自建 ISO/ANSI 螺纹表、攻丝计算器或标准管理框架。

建议合入仓库时将本研究稿放到 `CADExchange/doc/孔特征跨系统参数调研与统一映射方案_20261012.md`，再随实际实施补充已验证字段、同版本样件和明确不支持的组合。本文保持为设计稿，不替代各系统能力矩阵中的实测记录。
